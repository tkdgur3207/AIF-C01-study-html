Exam Study Notes & Prep Guidance(시험 학습 노트 및 준비 안내)

이 자료는 AWS Certified AI Practitioner(AWS 공인 AI 실무자, AIF-C01) 시험을 준비하며 원저자가 작성한 개인 학습 노트입니다.

이 자격증은 Foundational-level Certification(기초 수준 자격증)입니다. 원저자는 난이도가 AWS Certified Cloud Practitioner(AWS 공인 클라우드 실무자, CLF-C02)와 비슷하지만, AWS에서 사용하는 AI(인공지능), ML(Machine Learning, 기계 학습), Generative AI(생성형 AI)에 초점을 둔다고 설명합니다.

시험은 세부 구현보다는 전반적인 개념 이해를 중심으로 하며, 다음 내용을 다룹니다.

  • 핵심 AI(인공지능) 및 GenAI(Generative AI, 생성형 AI) 용어.
  • Responsible AI(책임 있는 AI)의 기초.
  • AWS AI/ML Services(AWS 인공지능·기계 학습 서비스)의 개념.
  • 간단한 Use Case(활용 사례)에 적합한 서비스나 접근 방식 연결하기.

Overview(전체 개요)

General AI(일반 AI — 원문에서 AGI와 혼동한 항목)

  • 정의: 인간이 수행할 수 있는 모든 지적 과제를 수행하는 시스템을 만들려는, 더 넓은 의미의 인공지능 개념을 가리킵니다. 높은 자율성과 유연성을 갖춘 AI 시스템을 만들려는 장기 목표를 설명할 때 자주 사용됩니다.
  • 핵심 개념: 특정 과제에 특화된 AI와 달리, 여러 분야에 걸쳐 다양한 과제를 수행할 수 있는 폭넓은 능력입니다.
  • 원문의 예시: Expert Systems(전문가 시스템), Rules Engines(규칙 엔진). MYCIN처럼 미리 정의한 논리와 규칙을 사용하여 의사결정합니다.
[검증 및 정정]위 정의는 AI(인공지능) 전체보다는 AGI(Artificial General Intelligence, 범용 인공지능)를 설명합니다. Expert Systems(전문가 시스템)와 Rules Engines(규칙 엔진)는 특정 영역의 문제를 다루는 사례로, AGI(범용 인공지능)의 구현 사례가 아닙니다. AI(인공지능)와 AGI(범용 인공지능)를 구분해 학습하세요. [S01]

Machine Learning(기계 학습, ML)

  • 정의: AI(인공지능)의 하위 분야입니다. 모든 규칙을 명시적으로 프로그래밍하지 않고도 시스템이 데이터로부터 학습하여 예측하거나 의사결정하게 합니다.
  • 핵심 개념: 사람이 일일이 작성한 명령보다는 데이터의 패턴과 Training(학습)을 통해 동작합니다.
  • 예시: Linear Regression(선형 회귀), Decision Trees(의사결정 트리), Support Vector Machines(서포트 벡터 머신). 예측 과제에 사용하는 Supervised Learning(지도 학습) 알고리즘입니다.

Deep Learning(딥러닝)

  • 정의: Machine Learning(기계 학습)의 하위 분야로, 여러 층으로 이루어진 Neural Networks(신경망)를 사용해 데이터의 복잡한 패턴을 모델링합니다. 여러 층이라는 점에서 deep(깊은)이라는 이름이 붙습니다.
  • 핵심 개념: Image Recognition(이미지 인식), Natural Language Processing(자연어 처리), 자율 시스템 같은 과제에 효과적입니다.
  • 예시: 이미지 처리에는 CNNs(Convolutional Neural Networks, 합성곱 신경망), Time-Series(시계열)나 언어처럼 순서가 있는 데이터에는 RNNs(Recurrent Neural Networks, 순환 신경망)를 사용합니다.

Generative AI(생성형 AI)

  • 정의: 원문은 Deep Learning(딥러닝)의 하위 분야 중, 학습한 데이터를 바탕으로 텍스트·이미지·음악 등의 새로운 콘텐츠를 만드는 분야로 설명합니다. Generative AI Models(생성형 AI 모델)은 일반적으로 Foundation Models(기반 모델)을 바탕으로 합니다. 이는 대규모로 Pre-training(사전 학습)되어 다양한 과제에 맞게 적용할 수 있는 모델입니다.
  • 핵심 개념: Training(학습) 중 익힌 패턴을 바탕으로 새로운 출력을 생성합니다. Foundation Models(기반 모델)은 특정 과제에 맞게 Fine-Tuning(미세 조정)할 수 있는 범용성을 제공합니다.
  • 예시: 텍스트 생성용 ChatGPT(대화형 생성 AI), 이미지 생성용 DALL·E(이미지 생성 모델), 예술적인 시각 표현을 만드는 DeepDream(신경망 기반 이미지 시각화 기법).
[학습 보충]여기의 포함 관계는 현대의 주요 Deep Learning(딥러닝) 기반 시스템을 설명하는 학습용 구도입니다. 모든 생성 모델이 대규모 Foundation Model(기반 모델)인 것은 아니며, Fine-Tuning(미세 조정)이 사용의 필수 조건도 아닙니다.

Large Language Models(대규모 언어 모델, LLMs)

  • 정의: 원문은 사람과 유사한 텍스트를 이해하고 생성하는 Generative AI(생성형 AI)의 한 유형으로 설명합니다. 대량의 텍스트 데이터에서 언어 패턴, 문법, 문맥을 학습합니다.
  • 핵심 개념: 입력 Prompt(프롬프트, 모델에 주는 지시·입력)를 바탕으로 일관성 있는 고품질 텍스트를 생성하며, 요약·번역·질의응답 등의 과제를 수행할 수 있습니다.
  • 원문의 예시: GPT-4(언어 모델), BERT(양방향 언어 표현 모델), T5(텍스트를 텍스트로 변환하는 모델), Claude 2(언어 모델). 텍스트 생성, Sentiment Analysis(감정 분석), 요약, Natural Language Understanding(자연어 이해)에 활용합니다.
[검증 및 정정]LLM(대규모 언어 모델)을 모두 대화형 텍스트 생성 모델로 이해하면 안 됩니다. BERT(양방향 언어 표현 모델)는 Encoder(인코더) 기반의 언어 이해 모델로, GPT 계열과 같은 방식의 자유로운 다음 Token(토큰) 생성 모델이 아닙니다. 예시 모델명은 원문을 보존한 것이며 최신 모델 목록을 뜻하지 않습니다. [S02]

Concepts(핵심 개념)

In-Context Learning(문맥 내 학습)

  • 정의: Prompt(프롬프트)에 추가 정보와 예시를 넣어, Generative AI Model(생성형 AI 모델)이 과제를 더 잘 해결하도록 하는 방법입니다.
[학습 보충]여기서 learning(학습)은 입력 문맥을 활용한다는 뜻입니다. 일반적인 In-Context Learning(문맥 내 학습)은 모델의 Weights(가중치)를 다시 학습하거나 변경하지 않습니다.

Prompt Types(프롬프트 유형)

  • Few-Shot Prompt(소수 예시 프롬프트): 몇 개의 예시를 넣어 모델이 원하는 방식으로 동작하도록 유도합니다.
  • Zero-Shot Prompt(예시 없는 프롬프트): 예시 없이 과제를 수행하도록 요청합니다.
  • One-Shot Prompt(단일 예시 프롬프트): 정확히 한 개의 예시를 제공해 모델의 동작을 유도합니다.
  • Prompt Template(프롬프트 템플릿): AI 모델과의 상호작용을 표준화하고 개선하기 위해 미리 정해 둔 입력 형식이나 구조입니다.
  • Chain-of-Thought Prompting(사고 과정 유도 프롬프팅): 문제를 단계적으로 나누어 추론하도록 유도하는 프롬프트 방식입니다.
  • Prompt Tuning(프롬프트 튜닝): 원문은 특정 과제의 성능을 높이기 위해 프롬프트를 조정하는 과정이라고 설명합니다.
[검증 및 정정]Zero-Shot(제로샷)은 예시가 없다는 뜻이지 Instructions(지시) 자체가 없다는 뜻은 아닙니다. 또한 기술적으로 Prompt Tuning(프롬프트 튜닝)은 보통 모델 본체의 Weights(가중치)는 고정하고 Soft Prompts(학습 가능한 연속형 프롬프트 벡터)를 학습하는 기법을 가리킵니다. 사람이 프롬프트 문구를 수정하는 Prompt Engineering(프롬프트 엔지니어링)과 구분하세요. [S03]

Latent Space(잠재 공간)

  • 정의: 원문은 LLMs(대규모 언어 모델)가 포착한 지식이나 패턴을 인코딩해 데이터 사이의 관계를 담는 공간이라고 설명합니다.
  • 용도: AI 모델이 출력을 만들 때 활용하는 언어나 데이터의 내부 표현을 나타냅니다.
[학습 보충]Latent Space(잠재 공간)는 LLM(대규모 언어 모델)에만 쓰는 말이 아닙니다. 데이터의 특성이나 관계를 수치 표현으로 나타내는 내부 표현 공간이며, VAE(Variational Autoencoder, 변분 오토인코더)나 Latent Diffusion(잠재 확산)에서도 중요합니다. 사실이 그대로 저장된 검색용 문서 보관함으로 이해하지 마세요. [S13]

Embeddings(임베딩)

  • 정의: Tokens(토큰), 단어, 구절 등의 의미적 특성을 담은 수치 Vector(벡터) 표현입니다.
  • 활용 사례: 단어나 입력의 의미를 반영해야 하는 Semantic Search(의미 기반 검색)에 사용합니다.
  • 저장: 효율적인 검색과 Retrieval(정보 검색·조회)을 위해 Vector Database(벡터 데이터베이스)에 저장할 수 있습니다.

Tokens(토큰)

  • 정의: 언어 모델이 처리하는 텍스트의 기본 단위입니다. 단어 전체, Subword(하위 단어), 문자 등이 될 수 있습니다. LLM(대규모 언어 모델)의 입력 텍스트와 생성된 출력 모두 Tokens(토큰)로 표현됩니다.

Context-Window(문맥 창)

  • 정의: LLM(대규모 언어 모델)이 한 번에 처리할 수 있는 최대 Tokens(토큰) 수입니다. 일반적으로 입력 Prompt(프롬프트)와 생성되는 출력을 함께 고려합니다. 한도를 넘으면 앞부분이 잘릴 수 있습니다.
  • 용도: 모델에 한 번에 제공할 수 있는 정보량을 결정하는 주요 요인입니다. 긴 글 생성, 문서 분석, 여러 차례 이어지는 대화에 영향을 줍니다.
[학습 보충]한도 초과 시 항상 자동으로 앞부분이 삭제되는 것은 아닙니다. 모델·API(응용 프로그램 인터페이스)·애플리케이션 설정에 따라 요청이 거부되거나 입력이 잘릴 수 있으며, 별도의 최대 출력 한도도 있을 수 있습니다.

Hallucinations(환각, 사실에 근거하지 않은 생성)

  • 정의: 언어 모델이 그럴듯하지만 사실 데이터나 제공된 입력에 근거하지 않은, 잘못되거나 앞뒤가 맞지 않는 정보를 생성하는 현상입니다.
  • 완화 방법:
    • Retrieval Augmented Generation(검색 증강 생성, RAG): 생성 과정에서 관련 외부 정보를 검색하여 사실 자료에 근거한 답변을 만들도록 돕습니다. 원문은 이를 통해 정확한 정보에 기반한 답변을 보장한다고 표현합니다.
    • Fine-Tuning(미세 조정): 관련성이 높고 정확한 데이터로 추가 학습하여 출력이 사실적 지식에 더 부합하도록 하면 Hallucinations(환각)를 줄이는 데 도움이 될 수 있습니다.
    • Human-in-the-Loop(사람이 참여하는 검토·의사결정 구조, HITL): 신뢰도가 낮은 결과를 사람이 검토하여 중요한 용도에 잘못된 출력이 사용되는 것을 막습니다.
[검증 및 정정]RAG(검색 증강 생성)는 관련 근거를 제공하여 답변의 신뢰성을 높이는 방법입니다. 검색 오류나 생성 오류가 남을 수 있으므로 사실 정확성을 보장하지 않습니다. Fine-Tuning(미세 조정) 역시 환각 제거를 보장하지 않습니다. 최신 사내 문서를 참고하는 것과 모델의 Weights(가중치)를 바꾸는 것을 구분하세요. [S15]

Multi-Modal Models(멀티모달 모델, 여러 유형의 데이터를 다루는 모델)

  • 정의: 텍스트·이미지·오디오 등 여러 Data Modalities(데이터 양식)를 다루는 모델입니다. 원문은 이 데이터를 공통 공간에 Embedding(임베딩)하는 방식으로 설명합니다. 이미지에 설명을 붙이거나 텍스트로 이미지를 만드는 등, 여러 유형의 입력을 활용하여 문맥을 더 잘 반영하는 출력을 생성하는 데 사용합니다.
[학습 보충]모든 Multi-Modal Model(멀티모달 모델)이 모든 데이터 양식의 입력과 출력을 지원하거나 반드시 하나의 공통 공간으로 표현하는 것은 아닙니다. 지원하는 입력·출력 조합은 모델마다 다릅니다.

Search Methods(검색 방식)

  • Keyword Search(키워드 검색): 검색어에 포함된 단어와 일치하는 항목을 찾습니다.
  • Semantic Search(의미 기반 검색): Embeddings(임베딩)를 이용해 검색어가 담고 있는 의미를 반영하여 관련성 높은 결과를 찾습니다.

Vector Databases(벡터 데이터베이스)

  • 정의: Vectors(벡터), 특히 Embeddings(임베딩)의 저장과 질의에 적합하게 설계된 데이터베이스입니다. Semantic Search(의미 기반 검색) 등에 유용합니다.

Vector Database Options on AWS(AWS의 벡터 데이터베이스 선택지)

  • Amazon OpenSearch Service(검색·로그 분석 서비스): k-nearest neighbor(k-최근접 이웃, k-NN) 검색을 지원합니다. 로그 분석, 실시간 애플리케이션 모니터링, 검색에 유용합니다.
  • Amazon Aurora PostgreSQL-Compatible Edition(PostgreSQL 호환 관계형 데이터베이스) 및 Amazon RDS for PostgreSQL(관리형 PostgreSQL 데이터베이스): pgvector(PostgreSQL용 벡터 저장·검색 확장)를 지원하여 Embeddings(임베딩) 저장 및 Similarity Search(유사도 검색)를 할 수 있습니다.
  • Amazon Neptune ML(그래프 기계 학습 기능): GNNs(Graph Neural Networks, 그래프 신경망)를 사용해 그래프 데이터를 바탕으로 예측합니다. 원문은 그래프 데이터베이스에서 벡터화된 데이터를 지원하는 선택지로 소개합니다.
  • Amazon MemoryDB(인메모리 데이터베이스): 밀리초 단위 질의와 초당 수만 건의 Queries Per Second(초당 질의 수, QPS)를 처리하는 빠른 벡터 저장·검색 기능을 지원한다고 설명합니다.
  • Amazon DocumentDB(MongoDB 호환 문서 데이터베이스): Vector Search(벡터 검색)를 지원하여 수백만 개 벡터의 저장·인덱싱·검색과 밀리초 단위 응답을 제공한다고 설명합니다.
[검증 및 정정]Amazon Neptune ML(그래프 기계 학습)과 Neptune Analytics(그래프 분석 엔진)의 Vector Similarity Search(벡터 유사도 검색)는 구분해야 합니다. 전자는 그래프 예측 모델을 학습·활용하는 기능이고, 후자는 그래프에 연결된 벡터의 유사도 검색을 명시적으로 지원합니다. 또한 위 처리량과 지연 시간은 모든 구성에서 보장되는 수치가 아닙니다. [S14]

The Machine Learning Pipeline(기계 학습 파이프라인)

ML Pipeline(기계 학습 파이프라인)은 모델을 구축하고, 학습시키고, 배포하는 체계적인 과정입니다. 비즈니스 목표 확인부터 배포된 모델 모니터링까지 각 단계를 관리하고 성능을 최적화하도록 돕습니다. 일반적인 단계는 다음과 같습니다.

  1. Identify Business Goal(비즈니스 목표 확인)
  2. Frame ML Problem(기계 학습 문제 정의)
  3. Collect Data(데이터 수집)
  4. Pre-Process Data(데이터 전처리)
  5. Engineer Features(특성 엔지니어링)
  6. Train, Tune, Evaluate(학습·조정·평가)
  7. Deploy(배포)
  8. Monitor(모니터링)

1. Identify Business Goal(비즈니스 목표 확인)

  • 설명: 성공 기준을 정의하고 이해관계자들의 목표를 일치시켜 ML(기계 학습) 프로젝트가 비즈니스 목표를 충족하게 합니다.
  • 주요 활동:
    • 명확한 Success Metrics(성공 지표)를 정합니다.
    • 조직의 이해관계자들과 목표 및 기대를 조율합니다.

2. Frame the ML Problem(기계 학습 문제 정의)

  • 설명: Feasibility(실현 가능성) 및 Cost-Benefit Analysis(비용 편익 분석)를 고려하면서 문제, 입력, 출력, 평가 지표를 정의합니다.
  • 주요 활동:
    • 입력, 출력, 요구사항, Performance Metrics(성능 지표)를 확인합니다.
    • 비용 편익 분석으로 실현 가능성을 평가합니다.
  • 모델 선택지:
    • AI/ML Hosted Service(호스팅되는 AI·기계 학습 서비스): Amazon Comprehend(텍스트 분석), Amazon Forecast(시계열 예측), Amazon Personalize(개인화 추천) 등. 원문은 별도 학습이 필요 없다고 설명합니다.
    • Pre-trained Models(사전 학습된 모델): Amazon Bedrock(기반 모델 활용 서비스), SageMaker JumpStart(사전 학습 모델 허브) 등을 사용하고 자체 데이터로 Fine-Tuning(미세 조정)할 수 있습니다.
    • Fully Custom Model(완전 맞춤형 모델): 처음부터 직접 구축하고 학습합니다.
[검증 및 정정]Managed Service(관리형 서비스)라고 해서 Training(학습)이 항상 불필요한 것은 아닙니다. Amazon Forecast(시계열 예측)는 사용자 데이터로 Predictor(예측 모델)를 학습하며, 개인화 서비스도 사용 방식에 따라 자체 데이터 학습이 필요합니다. Pre-trained Model(사전 학습 모델)은 추가 학습 없이 바로 사용할 수도 있습니다. [S16]

3. Collect Data(데이터 수집)

  • 설명: 모델 학습에 필요한 데이터를 수집하고 준비합니다.
  • 주요 활동:
    • Database(데이터베이스), Data Lake(데이터 레이크), 외부 API(응용 프로그램 인터페이스) 등 데이터 출처를 확인합니다.
    • Data Ingestion(데이터 수집·유입)과 Data Labeling(정답·분류 정보 부여)을 수행합니다.
  • 데이터 저장 위치:
    • ML(기계 학습)용 수집 데이터는 일반적으로 Amazon S3(객체 스토리지)에 저장합니다. 내부 시스템에서 가져온 데이터와 AWS Data Exchange(외부 데이터 구독·교환 서비스)로 접근한 외부 데이터셋 모두에 적용되는 일반적인 구성으로 설명합니다.
  • 도구:
    • AWS Glue(데이터 통합·변환 서비스): ETL(Extract, Transform, Load, 추출·변환·적재)을 수행하여 데이터를 사용하기 적합한 형태로 변환하고 Amazon S3(객체 스토리지)로 이동합니다.
    • SageMaker Ground Truth(학습 데이터 라벨링 서비스): 모호한 데이터를 사람이 라벨링하며, 결과를 Amazon S3(객체 스토리지)에 저장합니다.
    • AWS Data Exchange(외부 데이터 구독·교환 서비스): 외부 데이터셋에 안전하게 접근하여 추가 학습 데이터로 활용합니다. 원문은 수집된 데이터를 Amazon S3(객체 스토리지)에 저장하는 구성을 설명합니다.
    • Amazon S3(객체 스토리지): 수집한 데이터를 처리하거나 학습에 사용하기 전에 안전하게 보관하는 주요 저장 서비스입니다.
[학습 보충]모든 데이터가 반드시 Amazon S3(객체 스토리지)로 복사되는 것은 아닙니다. AWS Data Exchange(외부 데이터 구독·교환 서비스)의 제공 방식과 데이터 사용 구조에 따라 직접 질의하거나 API(응용 프로그램 인터페이스)로 접근할 수도 있습니다.

4. Pre-Process Data(데이터 전처리)

  • 설명: 데이터를 정리하고 준비하여 학습에 적합하게 만듭니다.
  • 주요 활동:
    • Exploratory Data Analysis(탐색적 데이터 분석, EDA)를 수행합니다.
    • 중복을 제거하고 Missing Values(결측값)를 처리하며, PII(Personally Identifiable Information, 개인 식별 정보)를 Anonymization(익명화)합니다.
    • 원문은 Training Set(학습 데이터셋) 80%, Validation Set(검증 데이터셋) 10%, Test Set(시험·최종 평가 데이터셋) 10%의 분할 예시를 제시합니다.
  • 데이터 정리 방법:
    • AWS Glue Transformations(글루 데이터 변환 기능): 중복 제거나 결측값 처리 등 내장 변환을 활용하고, Python(파이썬 프로그래밍 언어)이나 Spark(분산 데이터 처리 엔진)로 맞춤형 변환을 작성할 수 있습니다.
    • Macie for PII(개인 식별 정보 탐지에 사용하는 Macie): [원문 번역·오류 있음] Amazon Macie(민감 데이터 탐지 서비스)가 Amazon S3(객체 스토리지)의 민감 정보를 스캔하고 마스킹하여 PII(개인 식별 정보)를 탐지하고 익명화한다고 설명합니다.
    • AWS Glue DataBrew(시각적 데이터 준비 도구): 화면에서 데이터를 준비·정리하고 Data Quality Rules(데이터 품질 규칙)를 적용합니다. 변환 과정을 Recipes(재사용 가능한 변환 단계 모음)로 저장할 수 있습니다.
    • SageMaker Canvas(코드 없이 모델·데이터를 다루는 도구): 깊은 기술 지식 없이 데이터를 가져오고 변환·시각화합니다. 내장 변환을 단계별로 추가하며 각 단계를 화면의 흐름에서 확인할 수 있습니다.
  • 도구:
    • AWS Glue(데이터 통합·변환 서비스): 데이터 정리를 위한 내장 변환 기능을 갖춘 ETL(추출·변환·적재) 서비스입니다.
    • AWS Glue DataBrew(시각적 데이터 준비 도구): Recipes(변환 단계 모음)라는 변환 규칙을 정의·적용하고 내장 품질 검사 기능을 활용합니다.
    • SageMaker Canvas(코드 없는 데이터·모델 도구): 시각적인 No-code(코드 작성이 필요 없는) 인터페이스에서 데이터 가져오기, 준비, 변환을 수행합니다. 각 변환 단계가 작업 흐름에 표시됩니다.
[검증 및 정정]Amazon Macie(민감 데이터 탐지 서비스)의 핵심은 PII(개인 식별 정보) 등의 민감 정보 탐지·분류·보고입니다. 데이터를 직접 마스킹하거나 익명화하는 서비스로 외우지 마세요. 실제 익명화는 별도의 데이터 처리 기능이나 연계 작업으로 구성해야 합니다. 또한 80:10:10은 예시 비율이며 고정 규칙이 아닙니다. [S05]

5. Engineer Features(특성 엔지니어링)

  • 설명: 모델 성능을 높이는 Features(입력 특성)를 선택하고 가공합니다.
  • 주요 활동:
    • Feature Selection(특성 선택): Domain Knowledge(해당 분야의 지식)를 바탕으로 관련성이 높은 특성을 고릅니다. 차원을 줄이고 모델 효율을 개선합니다.
    • Feature Creation(특성 생성): 원시 데이터를 새로운 특성으로 변환합니다. Scaling(스케일 조정), Categorical Encoding(범주형 변수 인코딩), 기존 값에서 새로운 지표 계산 등이 예시입니다.
    • Feature Transformation(특성 변환): Normalization(정규화)이나 Standardization(표준화) 같은 수학·통계적 변환을 적용하여 Convergence(수렴)와 성능을 개선합니다.
  • Automated Feature Engineering(자동 특성 엔지니어링): SageMaker Autopilot(자동 모델 구축·학습·튜닝 기능)이 모델 성능에 도움이 되는 특성을 자동 생성하고 평가하도록 할 수 있습니다.
  • Dimensionality Reduction(차원 축소): PCA(Principal Component Analysis, 주성분 분석) 등으로 중요한 정보를 최대한 유지하면서 특성 수를 줄일 수 있습니다.
  • Feature Scaling(특성 스케일 조정): AWS Glue(데이터 통합·변환 서비스)나 원문에서 SageMaker DataBrew라고 부른 도구를 이용해 Normalization(정규화), Standardization(표준화)을 적용합니다. 원문은 각 특성이 학습에 균등하게 기여하도록 한다고 설명합니다.
  • Categorical Encoding(범주형 변수 인코딩): SageMaker Data Wrangler(시각적 데이터 준비 기능)나 AWS Glue(데이터 통합·변환 서비스)에서 One-hot Encoding(원-핫 인코딩) 또는 Target Encoding(목표값 기반 인코딩)으로 범주형 값을 숫자로 변환합니다.
  • 도구:
    • SageMaker Feature Store(특성 저장·공유 서비스): Features(특성)를 하나의 신뢰할 수 있는 기준 저장소에서 보관하고 관리합니다.
[검증 및 정정]DataBrew의 정식 명칭은 AWS Glue DataBrew(시각적 데이터 준비 도구)입니다. Feature Scaling(특성 스케일 조정)은 값의 크기 차이가 학습을 지나치게 지배하는 것을 줄이는 방법이며, 모든 특성의 중요도나 기여도를 같게 만든다는 뜻은 아닙니다.

6. Train, Tune, and Evaluate the Model(모델 학습·조정·평가)

  • 설명: 모델을 학습시키고, 설정을 조정하고, 성능을 평가합니다.
  • 주요 활동:
    • 반복적으로 학습하며 Parameters(모델 매개변수)를 조정합니다.
    • Epoch(전체 학습 데이터 1회 순회), Batch Size(한 번의 매개변수 갱신에 사용하는 표본 수), Learning Rate(학습률) 등의 Hyperparameters(하이퍼파라미터)를 조정하며 실험합니다.
    • Metrics(평가 지표)로 모델을 평가하고 성능을 비교합니다.

Parameters(매개변수)

  • Inference Parameters(추론 매개변수): Amazon Bedrock(기반 모델 활용 서비스)에서 모델별로 지원하는 생성 설정입니다.
    • Randomness and Diversity(무작위성과 다양성):
      • Temperature(샘플링의 무작위성을 조절하는 온도 값): 값이 높으면 더 다양하고 창의적인 출력이 나오는 경향이 있고, 낮으면 더 예측 가능하고 결정적인 출력에 가까워집니다.
      • Top K(확률 상위 K개 후보 제한): 확률이 가장 높은 K개의 Tokens(토큰) 중에서 다음 출력을 선택합니다. K가 작으면 후보가 줄어들어 결과가 더 예측 가능해지는 경향이 있습니다. 원문은 이를 더 안전한 선택이라고 표현합니다. 원저자는 Top K(상위 K개 제한)가 크게 유용하지 않으므로 Temperature(온도 값)나 Top-P(누적 확률 기반 후보 제한)를 사용하라는 의견도 제시합니다.
      • Top P(누적 확률 기반 후보 제한): 확률이 높은 순서로 누적했을 때 합이 P에 도달하는 최소 후보 집합에서 Tokens(토큰)를 선택합니다. 무작위성과 다양성을 조절합니다. [원문 번역·오류 있음] 원문은 Top P(누적 확률 기반 후보 제한)가 1에 가까울수록 확률이 높은 후보만 남으므로 무작위성이 줄어든다고 설명합니다.
      • Top-K vs Top-P(후보 수 제한과 누적 확률 제한의 비교): Top K(상위 K개 제한)는 후보 수를 고정하고, Top P(누적 확률 기반 제한)는 후보의 확률 합에 따라 후보 수가 달라집니다. 따라서 Top P(누적 확률 기반 제한)는 분포에 맞추어 후보 범위를 유동적으로 정합니다.
      • Temperature vs Top P(온도 값과 누적 확률 제한의 비교): Temperature(온도 값)는 확률 분포 자체를 조정하여 전체 후보의 선택 가능성에 영향을 줍니다. Top P(누적 확률 기반 제한)는 일정 누적 확률 범위에 포함되는 후보로 선택지를 제한합니다. 원문은 이를 무작위성과 정확성의 균형으로 설명합니다.
      • 사용 예시: 분포에 따라 후보 수를 조절하면서 비교적 확률이 높은 결과를 원하면 Top-P(누적 확률 기반 제한)를 사용하고, 전체 확률 분포의 무작위성을 조절하려면 Temperature(온도 값)를 사용합니다.
    • Response Length(응답 길이): 생성할 출력의 최대 길이 등을 지정하여 답변의 길이에 영향을 줍니다.
    • Penalties(반복 등에 대한 페널티): 반복되는 Tokens(토큰)나 문자열에 불이익을 주어 출력의 다양성을 유도합니다.
    • Stop Sequences(생성 중단 문자열): 특정 문자열이 생성되면 생성을 멈추도록 하여 출력 길이나 형식을 제어합니다.
[검증 및 정정]Top-P(누적 확률 기반 후보 제한)는 값이 커질수록 후보 범위가 넓어집니다. 다른 조건이 같다면 더 낮은 확률의 후보까지 포함될 수 있습니다. P=1은 누적 확률 기준으로 후보를 잘라내지 않는 설정이지, 무작위성이 가장 낮은 설정이 아닙니다. Top-K(상위 K개 제한)는 정식 추론 설정이며, 유용하지 않다는 평가는 원저자의 의견입니다. Temperature(온도 값), Top-K(후보 수), Top-P(누적 확률)는 사실 정확성이나 안전성을 보장하지 않습니다. 지원 설정·값 범위는 모델마다 다릅니다. [S04]
  • Model Training Parameters(모델 학습 설정), 즉 Hyperparameters(하이퍼파라미터):
    • Epoch(에포크, 전체 학습 데이터 1회 순회): 전체 데이터셋을 몇 번 반복해서 학습하는지 나타냅니다. Epochs(에포크 수)를 늘리면 더 많이 학습할 수 있지만, 너무 많으면 Overfitting(과적합)이 생길 수 있습니다. 일정 수준 이후에는 추가 학습으로 얻는 개선 폭이 줄어들 수 있습니다.
    • Batch Size(배치 크기): 모델의 Parameters(매개변수)를 한 번 갱신하기 전에 사용하는 표본 수입니다. 작으면 갱신이 잦아지며 수렴에 도움이 될 수 있지만 변동이 커질 수 있습니다. 크면 갱신이 더 안정적일 수 있지만 계산량과 메모리 요구량이 늘어날 수 있습니다.
    • Learning Rate(학습률): 학습 중 Parameters(매개변수)를 얼마나 크게 바꿀지 조절합니다. 높으면 빠르게 학습할 수 있지만 좋은 해를 지나칠 수 있습니다. 낮으면 학습이 느려질 수 있으나 세밀하게 수렴할 수 있습니다. 원문은 너무 낮을 경우 Local Minima(국소 최솟값)에 머물 위험이 있다고 설명합니다.
[학습 보충]Parameters(매개변수)는 학습으로 얻는 Weights(가중치) 등을 가리키고, Hyperparameters(하이퍼파라미터)는 학습 절차를 제어하는 설정을 가리킵니다. 작은 Batch Size(배치 크기), 낮은 Learning Rate(학습률), 많은 Epochs(에포크 수)가 항상 더 좋은 성능을 보장하는 것은 아닙니다. Validation Set(검증 데이터셋)의 결과로 판단합니다.

Error Metrics(오차 및 성능 평가 지표)

  • MSE(Mean Squared Error, 평균 제곱 오차): 예측값과 실제값의 차이를 제곱한 뒤 평균한 값입니다. 큰 오차에 더 큰 가중치가 적용됩니다. 모델 비교나 Hyperparameter Tuning(하이퍼파라미터 튜닝)에 활용합니다.
    • 활용 사례: 주택 가격이나 주식 가치 예측 같은 Regression(회귀) 문제.
    • 해석: 같은 평가 조건에서는 작을수록 좋습니다. 예측값이 실제값에 더 가깝다는 뜻입니다.
  • RMSE(Root Mean Squared Error, 평균 제곱근 오차): MSE(평균 제곱 오차)의 제곱근입니다. 예측 대상과 같은 단위로 표시되므로 해석하기 쉽습니다. 예측의 전형적인 오차 크기를 파악하는 데 사용합니다.
    • 활용 사례: 해석을 쉽게 하기 위해 Regression(회귀) 문제에서 MSE(평균 제곱 오차)와 함께 사용합니다.
    • 해석: 같은 평가 조건에서는 작을수록 성능이 좋습니다.
  • Perplexity(퍼플렉서티, 다음 토큰 예측의 불확실성을 나타내는 지표): 모델이 Tokens(토큰)의 연속을 얼마나 잘 예측하는지 평가합니다. 낮을수록 해당 데이터의 다음 Token(토큰)에 높은 확률을 부여한다는 뜻입니다.
    • 활용 사례: 문장에서 다음 단어를 잘 예측하는지 등 Language Model(언어 모델) 평가.
    • 해석: 동일한 평가 데이터와 Tokenization(토큰 분할) 조건에서 낮을수록 예측 성능이 좋습니다.
  • Precision(정밀도): Positive Prediction(양성으로 예측한 결과) 중 실제로 양성인 비율입니다. False Positives(거짓 양성)를 줄이는 것이 중요할 때 사용합니다.
    • 공식: TP / (TP + FP).
    • 활용 사례: Spam Detection(스팸 탐지) 등, 정상 사례를 잘못 양성으로 판단하는 일을 줄여야 하는 Classification(분류) 과제.
    • 해석: False Positive(거짓 양성)의 비용이 높다면 높은 Precision(정밀도)이 중요합니다.
  • Recall(재현율), TPR(True Positive Rate, 참 양성률): 실제 Positive(양성) 중 양성으로 정확히 예측한 비율입니다. False Negatives(거짓 음성)를 줄여야 할 때 사용합니다.
    • 공식: TP / (TP + FN).
    • 활용 사례: 질병 선별 검사처럼 실제 양성인 사례를 놓치면 안 되는 경우.
    • 해석: 실제 양성을 놓치는 비용이 크다면 높은 Recall(재현율)이 중요합니다.
  • False Positive Rate(거짓 양성률, FPR): 실제 Negative(음성) 중 잘못 양성으로 예측한 비율입니다.
    • 공식: FP / (FP + TN).
    • 활용 사례: 사기 탐지나 경보 시스템 등 False Alarm(오경보)을 줄여야 하는 보안 분야.
    • 해석: 낮을수록 오경보 비율이 낮습니다.
  • Specificity(특이도), TNR(True Negative Rate, 참 음성률): 실제 Negative(음성) 중 음성으로 정확히 예측한 비율입니다.
    • 공식: TN / (TN + FP).
    • 활용 사례: 질병이 없는 사람을 음성으로 정확하게 판별하는 검사.
    • 해석: 실제 음성을 정확히 가려내는 것이 중요하다면 높은 Specificity(특이도)가 중요합니다.
  • Accuracy(정확도): 모든 예측 중 올바른 예측, 즉 True Positives(참 양성)와 True Negatives(참 음성)의 비율입니다. 원문은 양성과 음성을 모두 중요하게 다룰 때 사용하는 지표로 설명합니다.
    • 공식: (TP + TN) / (TP + TN + FP + FN).
    • 활용 사례: 이미지 분류처럼 Class Balance(클래스 비율의 균형)가 비교적 잘 맞는 분류 과제.
    • 해석: 같은 조건에서 높을수록 전체적으로 맞힌 비율이 높습니다.
  • F1 Score(F1 점수): Precision(정밀도)과 Recall(재현율)의 Harmonic Mean(조화 평균)입니다. 두 지표의 균형이 필요할 때 사용합니다.
    • 공식: 2 × Precision × Recall / (Precision + Recall).
    • 활용 사례: 문서 분류 등 False Positives(거짓 양성)와 False Negatives(거짓 음성)가 모두 중요한 과제.
    • 해석: 높은 F1 Score(F1 점수)는 두 지표를 함께 고려한 성능이 좋다는 뜻입니다.
  • ROC Curve(Receiver Operating Characteristic Curve, 수신자 조작 특성 곡선): 여러 Thresholds(판정 임곗값)에서 FPR(거짓 양성률)을 가로축, TPR(참 양성률·재현율)을 세로축에 표시합니다. Sensitivity(민감도, 재현율)와 Specificity(특이도)의 관계를 평가하는 데 사용합니다.
    • 활용 사례: Binary Classification(이진 분류)의 여러 임곗값에 걸친 성능 비교.
    • 해석: ROC-AUC(ROC 곡선 아래 면적)가 클수록 일반적으로 양성과 음성을 구분하는 능력이 좋습니다.
[학습 보충]TP(True Positive, 참 양성)는 실제 양성을 양성으로 예측한 경우, FP(False Positive, 거짓 양성)는 실제 음성을 양성으로 예측한 경우입니다. TN(True Negative, 참 음성)은 실제 음성을 음성으로 예측한 경우, FN(False Negative, 거짓 음성)은 실제 양성을 음성으로 예측한 경우입니다. Positive(양성)는 문제에서 탐지하려는 대상이며 반드시 좋은 상태를 뜻하지 않습니다. Accuracy(정확도)는 Class Imbalance(클래스 불균형)가 큰 데이터에서는 단독으로 성능을 판단하기에 부족합니다. Precision(정밀도)과 Accuracy(정확도)를 같은 말로 외우지 마세요.

Model Training Issues(모델 학습 문제)

  • Overfitting(과적합): 원문은 같은 데이터로 지나치게 학습하여 모델이 해당 데이터에 과도하게 특화되는 현상으로 설명합니다.
    • 원문의 해결책: 더 다양한 학습 데이터를 사용합니다.
  • Underfitting(과소적합): 데이터에 있는 패턴을 충분히 학습하지 못하는 현상입니다.
    • 원문의 해결책: Epochs(에포크 수)를 늘리거나 데이터를 더 추가합니다.
  • Bias and Fairness(편향과 공정성): 학습 데이터의 다양성이 부족하면 편향된 예측이 발생할 수 있습니다.
    • 해결책: 다양성과 대표성을 갖춘 데이터를 확보하고 Fairness Constraints(공정성 제약조건)를 적용합니다.
[학습 보충]Overfitting(과적합)은 단순히 학습 시간이 길다는 뜻이 아니라, 학습 데이터에서는 좋지만 새 데이터로 Generalization(일반화)이 잘 되지 않는 상태입니다. Regularization(규제), Early Stopping(조기 종료), 모델 복잡도 조정 등도 해결책입니다. Underfitting(과소적합)은 모델이 너무 단순해서 생길 수도 있으므로, 데이터나 Epochs(에포크 수)만 늘린다고 반드시 해결되지는 않습니다. 데이터 다양성만으로 모든 Bias(편향)가 제거되는 것도 아닙니다.

Fine-Tuning(미세 조정)

  • 적용 서비스: Amazon Bedrock(기반 모델 활용 서비스), SageMaker(모델 구축·학습·배포 서비스).
  • 원문은 Pre-trained Model(사전 학습된 모델)의 Weights(가중치)를 자체 Labeled Data(라벨이 있는 데이터)로 조정하여 새로운 과제에 맞추는 과정으로 설명합니다.
  • 한 가지 과제의 지시만 제공하면 더 일반적인 능력을 잃는 Catastrophic Forgetting(파국적 망각)이 생길 수 있으므로 주의해야 합니다.
  • Domain Adaptation Fine-Tuning(도메인 적응 미세 조정): SageMaker(모델 구축·학습·배포 서비스)에서 법률·의료 등 특정 분야의 비교적 적은 데이터로 Foundation Model(기반 모델)을 그 분야에 맞춥니다. 해당 분야의 과제 성능을 개선하는 데 도움이 됩니다.
  • Instruction-based Fine-Tuning(지시 기반 미세 조정): 요약·분류 등 특정 과제의 Labeled Examples(정답이 있는 예시)를 제공해 모델이 원하는 과제를 더 잘 수행하도록 합니다. 정확한 형태의 출력이 필요한 과제에 유용합니다.
[학습 보충]위 설명은 주로 Supervised Fine-Tuning(지도 미세 조정)을 다룹니다. Fine-Tuning(미세 조정)을 언제나 사람이 라벨을 붙인 데이터만 사용하는 모든 추가 학습의 동의어로 외우지 마세요. Domain Adaptation(도메인 적응)은 목적을 나타내며, 라벨 없는 도메인 텍스트로 추가 사전 학습하는 방식도 있습니다. 데이터 형식과 지원 학습 방식은 모델별로 구분합니다. [S17] [S18]

Continued-Pretraining(지속 사전 학습)

  • 원문 적용 서비스: Amazon Bedrock(기반 모델 활용 서비스).
  • Unlabeled Data(라벨이 없는 데이터)로 추가 학습하여 모델의 전반적인 지식을 확장합니다. 특정 하나의 과제만 수행하도록 범위를 좁히는 것과 구분합니다.

Transfer Learning(전이 학습)

  • 일반적인 Features(특성)를 이미 학습한 모델을 새로운 문제에 적용하여 학습 속도를 높이고 정확도를 개선합니다. 원문은 기존 모델을 Fine-Tuning(미세 조정)하는 방식으로 설명합니다.
[학습 보충]Transfer Learning(전이 학습)은 Fine-Tuning(미세 조정)보다 넓은 개념입니다. 사전 학습 모델을 고정한 채 Feature Extractor(특성 추출기)로 활용하는 방식도 포함합니다. 학습 방식의 서비스 지원 여부는 모델과 지역에 따라 확인해야 합니다.

Training Tools(학습 도구)

  • SageMaker Training Jobs(학습 작업 관리 기능): 학습 프로세스를 관리하고 학습 데이터, Hyperparameters(하이퍼파라미터), Compute Resources(컴퓨팅 자원)를 지정합니다.
  • SageMaker Experiments(기계 학습 실험 추적 기능): 모델 실행과 Hyperparameter Tuning(하이퍼파라미터 튜닝)을 추적합니다.
  • Automatic Model Tuning(자동 모델 튜닝, AMT): 지정한 평가 지표를 기준으로 Hyperparameters(하이퍼파라미터)를 자동 조정합니다.

7. Deploy the Model(모델 배포)

  • 설명: 학습한 모델을 배포하여 예측에 사용합니다.

SageMaker Deployment Options(SageMaker 배포 선택지)

  • Real-Time Inference(실시간 추론): 지속적으로 요청이 들어오고 낮은 Latency(지연 시간)가 필요한 예측에 적합하며 Auto Scaling(자동 확장·축소)을 사용할 수 있습니다.
  • Batch Transform(배치 변환): 대량의 데이터를 한꺼번에 비동기 방식으로 처리합니다.
  • Asynchronous Inference(비동기 추론): 처리 시간이 길고 Payload(요청 데이터 크기)가 큰 요청에 적합합니다. 즉시 결과를 반환하지 않아도 되는 작업을 다룹니다.
  • Serverless Inference(서버리스 추론): 요청이 간헐적으로 발생하는 경우에 적합하며, 사용자가 인프라를 직접 관리하지 않아도 모델 실행 자원이 자동 확장·축소됩니다.

Bedrock Deployment Mechanisms(Bedrock의 추론 제공 및 작업 실행 방식)

  • On-Demand Inference(온디맨드 추론): 원문은 입력·출력 Tokens(토큰) 수에 따라 사용량만큼 비용을 내는 방식으로 설명합니다. 이용량이 적거나 불규칙한 경우에 적합합니다.
  • Provisioned Throughput(프로비저닝된 처리량, 예약 추론 용량): 일관되게 높은 처리량이 필요한 추론을 위해 전용 용량을 확보합니다. 원문은 Custom Models(맞춤형 모델)나 Fine-tuned Models(미세 조정 모델)에 필수라고 설명합니다.
  • Bedrock Agents(Bedrock의 다단계 작업 에이전트): 모델을 Amazon Kendra(기업 문서 검색 서비스), AWS Lambda(서버리스 함수 실행 서비스) 같은 도구와 연계하여 복잡한 여러 단계의 작업을 실행합니다.
[검증 및 정정]현재 공식 문서는 일부 Custom Models(맞춤형 모델)에 On-Demand Inference(온디맨드 추론)를 배포하는 방법도 안내합니다. 따라서 모든 맞춤형 모델에 Provisioned Throughput(예약 추론 용량)이 반드시 필요하다고 일반화하면 안 됩니다. 모델·학습 방식·지역별 지원 범위를 확인해야 합니다. Bedrock Agents(작업 에이전트)는 추론 요금 방식과 구분되는 작업 조정 기능입니다. [S07]

Deployment Tools(배포 도구)

  • Amazon API Gateway(API 게이트웨이 서비스): 모델을 API Endpoint(API 호출 주소) 형태로 제공하여 애플리케이션과 연결합니다.
  • Amazon API Gateway(API 게이트웨이 서비스, 선택 사항): 모델을 RESTful API(REST 방식의 응용 프로그램 인터페이스)로 노출하여 다른 애플리케이션이나 Microservices(작은 독립 서비스)와 연계할 때 사용할 수 있습니다. 외부 애플리케이션에서 모델 호출 창구를 제공하려는 경우에 활용하는 선택 사항입니다. 원문에 유사한 도구 설명이 두 번 나옵니다.
  • SageMaker Deployment(SageMaker 배포): 원문은 Amazon ECR(컨테이너 이미지 저장소)에 저장한 Docker Images(도커 컨테이너 이미지)를 사용하며, 활용 사례에 따라 AWS Lambda(서버리스 함수 실행), Amazon EC2(가상 서버), Amazon EKS(관리형 쿠버네티스), Amazon ECS(관리형 컨테이너 실행)에 배포한다고 설명합니다.
  • Instance Types(인스턴스 유형)의 원문 예시:
    • Inf1(인퍼런시아 기반 추론 인스턴스): AWS Inferentia(추론용 가속기 칩)를 사용하여 비용 효율이 높은 Deep Learning Inference(딥러닝 추론)를 제공합니다.
    • P4(A100 GPU 기반 인스턴스): NVIDIA A100 GPUs(그래픽 처리 장치)를 사용하며, 대규모 고성능 추론에 활용할 수 있다고 설명합니다.
    • G5(GPU 기반 인스턴스): NVIDIA GPUs(그래픽 처리 장치)를 사용하는 그래픽 및 ML Inference(기계 학습 추론) 작업용 인스턴스입니다.
    • Graviton2(ARM 기반 프로세서), C6g·M6g(해당 프로세서 기반 인스턴스 유형): 전력 효율이 높은 ARM Architecture(ARM 명령어 체계)를 사용하며, 원문은 일반적인 ML Inference(기계 학습 추론)의 예시로 소개합니다.
  • SageMaker Endpoints(SageMaker 모델 호출 엔드포인트): 원문은 배포 후 Real-Time Inference(실시간 추론)나 Batch Transform Jobs(배치 변환 작업)를 위한 모델 제공 창구로 설명합니다.
  • Bedrock Deployment(Bedrock 관련 실행 구성):
    • AWS Lambda(서버리스 함수 실행 서비스): Bedrock Agents(작업 에이전트)와 연계하여 여러 단계의 작업을 자동화할 수 있습니다.
    • Amazon Kendra(기업 문서 검색 서비스): 문서 검색과 지식 기반 작업을 위해 연결할 수 있습니다.
    • Provisioned Throughput Tools(예약 추론 용량 관리 도구): AWS Management Console(AWS 관리 콘솔)이나 Bedrock API(Bedrock 응용 프로그램 인터페이스)로 추론 용량을 확보합니다.
[검증 및 정정]SageMaker Serverless Inference(서버리스 추론)는 SageMaker가 Compute Resources(컴퓨팅 자원)를 관리하는 Endpoint(모델 호출 창구)입니다. 사용자가 모델을 Lambda Function(람다 함수)으로 배포하는 방식이라고 외우면 안 됩니다. EC2·EKS·ECS에 직접 컨테이너를 운영하는 구성도 SageMaker의 관리형 Endpoint(엔드포인트)와 구분합니다. 또한 Batch Transform(배치 변환)은 지속적인 Endpoint(엔드포인트) 없이 실행하는 별도의 작업 방식입니다. 인스턴스 예시는 특정 Latency(지연 시간)를 보장하지 않습니다. [S06]

8. Monitor the Model(모델 모니터링)

  • 설명: 모델 성능을 지속적으로 관찰하고 Data Drift(데이터 드리프트)나 Concept Drift(개념 드리프트)를 탐지합니다.
  • 주요 활동:
    • 운영 중인 모델의 데이터 및 개념 변화를 모니터링합니다.
    • 성능이 나빠지면 알림을 보내고 수정 작업이 실행되도록 구성합니다.
  • Drift Types(드리프트 유형):
    • Data Drift(데이터 드리프트): 입력 데이터의 분포가 바뀌는 현상입니다. 원문은 입력과 출력의 관계는 그대로인 경우로 설명하며, 이용자 인구통계 특성 변화 등을 예로 듭니다.
    • Concept Drift(개념 드리프트): 입력과 출력 사이의 관계가 바뀌어 모델이 학습한 패턴이 더 이상 잘 맞지 않는 현상입니다. 새롭게 나타난 사기 수법 등이 예시입니다.
  • 도구:
    • SageMaker Model Monitor(모델·데이터 품질 모니터링 기능): Data Drift(데이터 드리프트)를 주기적으로 검사하고 결과를 CloudWatch(운영 지표·로그·경보 서비스)에 보내며, 후속 수정 작업을 자동화하는 구성에 활용합니다.
[학습 보충]Data Drift(데이터 드리프트)와 Concept Drift(개념 드리프트)는 함께 발생할 수도 있습니다. 입력 분포만 보고 입력·출력 관계 변화까지 자동으로 입증할 수 있는 것은 아닙니다. Model Monitor(모델 모니터링)의 탐지·알림과 모델 Retraining(재학습) 실행은 구분하며, 자동 재학습은 별도의 작업 흐름으로 연결합니다. 공식 문서에는 Model Monitor(모델 모니터링)의 신규 고객 이용 제한도 안내되어 있으므로 실습 시 현재 이용 가능 여부를 확인해야 합니다. 이는 시험 출제 여부에 대한 판단은 아닙니다. MLOps and Automation(기계 학습 운영과 자동화)

  • 설명: ML Models(기계 학습 모델)의 전체 Lifecycle(생애주기)에 DevOps(개발·운영 협업 및 자동화)의 원칙을 적용합니다. 자동화, Version Control(버전 관리), Monitoring(모니터링)에 초점을 둡니다.
  • 주요 활동:
    • 모델의 배포, 모니터링, Retraining(재학습)을 자동화합니다.
    • 모델 업데이트를 위한 CI/CD(Continuous Integration and Continuous Delivery, 지속적 통합 및 지속적 제공) 체계를 마련합니다.
    • 여러 모델 버전을 관리할 수 있도록 Version Control(버전 관리)을 적용합니다.
  • 도구:
    • SageMaker Pipelines(기계 학습 작업 흐름 조정 기능): 전체 ML Workflow(기계 학습 작업 흐름)를 자동화하고 관리합니다.
    • AWS CodePipeline(소프트웨어 제공 파이프라인 서비스): 모델의 Build(빌드), Test(테스트), Deploy(배포) 단계를 자동화합니다.
    • SageMaker Model Registry(모델 버전 등록·관리 기능): 모델 버전과 Metadata(메타데이터)를 관리·추적합니다.
    • Amazon S3(객체 스토리지): [원문 번역·과도한 일반화] SageMaker(모델 구축·학습·배포 서비스)와 Bedrock(기반 모델 활용 서비스)에서 학습한 모델의 Artifacts(모델 산출물)를 저장합니다. 원문은 Weights(가중치)와 산출물 등을 모두 S3로 내보내 배포·평가에 쉽게 접근한다고 설명합니다.
[검증 및 정정]SageMaker(모델 구축·학습·배포 서비스)의 모델 산출물을 Amazon S3(객체 스토리지)에 저장하는 것과, Bedrock(기반 모델 활용 서비스)의 맞춤형 모델 가중치를 내려받는 것은 같은 기능이 아닙니다. Bedrock(기반 모델 활용 서비스)의 사용자 지정 S3 출력 경로에는 학습·검증 Loss Metrics(손실 지표) 같은 작업 결과가 저장됩니다. 이 설정만으로 모든 모델의 Weights(가중치)를 사용자 버킷으로 내보낼 수 있다고 이해하지 마세요. 모델·기능별 내보내기 지원을 구분해야 합니다. [S08] [S19]

Model Governance and Explainability(모델 거버넌스와 설명 가능성)

    • 감사에 대비하여 모델 이력과 성능을 명확히 문서화합니다.

    • ML Governance from SageMaker(SageMaker의 기계 학습 관리·통제 기능): 모델을 더 세밀하게 통제하고 모델 정보나 편향 같은 동작 특성을 확인하도록 돕습니다.
    • SageMaker ML Lineage Tracking(기계 학습 계보 추적 기능): 전체 작업 흐름과 모델의 생성 이력을 추적하여 Reproducibility(재현 가능성)와 Governance(관리·통제)를 지원합니다.
    • AWS Glue DataBrew(시각적 데이터 준비 도구): 시각적인 데이터 준비와 품질 규칙으로 데이터 관리 작업을 돕습니다.
    • AWS Audit Manager(감사 증거 수집·관리 서비스): 원문은 AWS 서비스 감사 과정을 자동화하여 지속적인 규정 준수와 감사 준비를 보장한다고 표현합니다.
    • AWS Artifact(규정 준수 보고서·계약 제공 서비스): 필요할 때 Compliance Reports(규정 준수 보고서)와 Agreements(계약서)에 접근하여 조직의 규정 준수 업무에 활용합니다.
    • AWS AI Service Cards(AWS AI 서비스의 용도·한계 설명 자료): 활용 사례, 한계, Responsible AI(책임 있는 AI) 관행, 성능 관련 권장 사용법을 제공하여 투명성을 높입니다.
[검증 및 정정]AWS Audit Manager(감사 증거 수집·관리 서비스)는 Evidence Collection(증거 수집)과 평가 보고서 준비를 돕습니다. 조직의 규정 준수 여부를 스스로 최종 판정하거나 준수를 보장하지 않습니다. AWS Artifact(규정 준수 보고서 제공 서비스)의 보고서를 확보하는 것만으로 조직의 모든 의무가 충족되는 것도 아닙니다. [S10]

Cost and Performance Optimization(비용 및 성능 최적화)

  • 도구:

Continual Learning and Retraining(지속 학습과 재학습)

  • 주요 활동:

    • Concept Drift(개념 드리프트)와 Data Drift(데이터 드리프트)를 모니터링하여 변화에 대응합니다.
  • 도구:
    • SageMaker Model Monitor(모델·데이터 품질 모니터링 기능): Data Drift(데이터 드리프트)를 감지하고 후속 재학습 흐름을 시작하는 구성에 활용합니다.

[학습 보충]Continual Learning(지속 학습)과 주기적으로 수행하는 Retraining(재학습)은 관련 있지만 완전히 같은 학습 방식은 아닙니다. 원문은 새로운 상황에 맞춰 모델을 계속 갱신한다는 운영 관점에서 함께 설명합니다. 자동 갱신 후에도 평가와 배포 승인 기준을 적용해야 합니다.

Security(보안)

  • 설명: ML Models(기계 학습 모델), 데이터, 관련 인프라를 보호하기 위해 보안 권장 사항을 적용합니다.
  • 주요 활동:
    • Least Privilege Principle(최소 권한 원칙): IAM Roles and Policies(자격·접근 관리 역할과 정책)에 특정 작업이나 기능에 필요한 권한만 부여합니다.
    • PrivateLink and VPC Endpoints(프라이빗 연결 기능과 VPC 엔드포인트): SageMaker(모델 구축·학습·배포 서비스)의 자원과 통신이 불필요하게 인터넷에 노출되지 않도록 사설 연결을 구성합니다.
    • Encryption at Rest and in Transit(저장 중·전송 중 암호화): [원문 번역·오류 있음] 원문은 SageMaker(모델 구축·학습·배포 서비스)가 기본적으로 KMS(Key Management Service, 암호화 키 관리 서비스)를 이용해 저장 중과 전송 중 데이터를 모두 암호화한다고 설명합니다.
    • IAM Roles and Policies(자격·접근 관리 역할과 정책): 모델 데이터와 자원에 안전하게 접근하도록 역할과 정책을 생성·관리합니다.
    • S3 Block Public Access(S3 퍼블릭 액세스 차단): 공개 접근을 허용하는 설정이 있더라도 차단 설정이 적용되도록 하여 모델 데이터의 의도하지 않은 노출을 막습니다.
    • AWS IAM Identity Center(중앙 사용자 접근 관리 서비스): 여러 AWS 계정에 대한 사용자 접근을 중앙 관리하며 Active Directory(디렉터리 기반 사용자 관리 체계)와 연동할 수 있습니다.
  • 도구:
    • AWS Config(AWS 자원 구성 기록·평가 서비스): 자원 구성 변경을 계속 기록·관찰하고 규정 준수와 보안 평가에 활용합니다.
    • AWS CloudTrail(AWS 계정 활동·API 호출 기록 서비스): API Calls(API 호출)와 사용자 활동을 기록하여 감사와 규정 준수 업무를 지원합니다.
    • Amazon Inspector(워크로드 취약점 관리 서비스): 지원되는 기계 학습 운영 자원의 취약점을 자동 검사합니다.
    • AWS Audit Manager(감사 증거 수집·관리 서비스): 감사 자료와 평가 보고서를 준비하는 작업을 자동화하여 규정 준수 검토를 돕습니다. 원문은 규정 준수를 보장한다고 표현합니다.
    • AWS Artifact(규정 준수 보고서·계약 제공 서비스): 기계 학습 환경의 규정 준수 검토에 필요한 AWS 보안·규정 준수 문서를 제공합니다.
    • SageMaker Role Manager(SageMaker 역할·권한 설정 지원 기능): SageMaker 자원과 서비스에 대한 역할·권한 관리를 간소화합니다.
[검증 및 정정]Encryption at Rest(저장 중 암호화)에는 자원과 설정에 따라 S3 기본 암호화, KMS(암호화 키 관리) 등이 관련됩니다. Encryption in Transit(전송 중 암호화)은 주로 TLS(Transport Layer Security, 전송 계층 보안)로 보호합니다. 모든 전송이 KMS(키 관리 서비스)로 자동 암호화된다는 설명은 잘못입니다. 일부 분산 학습·처리 노드 간 통신은 별도 암호화 설정도 확인해야 합니다. PrivateLink(프라이빗 연결) 역시 모든 형태의 Endpoint(엔드포인트)에서 모든 외부 통신을 자동 차단하는 기능으로 이해하면 안 됩니다. [S09]
[검증 및 정정]AWS Config(자원 구성 기록·평가), CloudTrail(활동 기록), Inspector(취약점 검사), Audit Manager(감사 증거 관리), Artifact(준수 보고서 제공)는 역할이 다릅니다. 특히 감사 도구를 사용하는 것만으로 규정 준수나 모델 보안이 보장되지는 않습니다. [S10] [S11]

Services(서비스)

AWS Managed AI Services(AWS 관리형 AI 서비스)

AWS는 깊은 ML(기계 학습) 전문 지식이 없어도 애플리케이션에 AI(인공지능) 기능을 연동할 수 있도록 여러 관리형 서비스를 제공합니다. 주요 서비스는 다음과 같습니다.

Computer Vision(컴퓨터 비전)

  • Amazon Rekognition(이미지·동영상 분석 서비스): 얼굴 비교·분석, Object Detection(객체 탐지), Text Detection(텍스트 탐지), Content Moderation(콘텐츠 검토·조정)을 수행합니다. 폭력적이거나 부적절한 자료를 찾아내는 등 콘텐츠 선별에 유용합니다.

Text and Document Analysis(텍스트 및 문서 분석)

  • Amazon Textract(문서 텍스트·구조 추출 서비스), OCR(Optical Character Recognition, 광학 문자 인식): 스캔 이미지에서 텍스트를 추출하여 디지털 문서 관리에 활용합니다.
  • Amazon Comprehend(자연어 텍스트 분석 서비스), NLP(Natural Language Processing, 자연어 처리): 텍스트의 Key Phrases(핵심 구절), Entities(개체), Sentiment(감정)를 추출합니다. 피드백의 감정 분석과 PII(개인 식별 정보) 탐지에 유용합니다.
  • AWS Intelligent Document Processing(지능형 문서 처리, IDP): 여러 AWS 서비스를 조합하여 다양한 문서의 데이터 추출·분류·처리를 자동화하는 접근 방식입니다. OCR(광학 문자 인식), NLP(자연어 처리), ML(기계 학습)을 활용해 PDF(전자 문서 형식), 청구서, 법률 계약서 등에 들어 있는 Unstructured Data(비정형 데이터)를 처리합니다.
[학습 보충]IDP(지능형 문서 처리)는 하나의 독립된 제품 이름이라기보다 여러 서비스를 조합하는 솔루션·작업 흐름입니다. Textract(문서 추출), Comprehend(텍스트 분석), A2I(사람 검토 연계) 등의 역할을 구분하세요.

Language AI(언어 AI)

  • Amazon Lex(대화형 인터페이스 구축 서비스): 음성과 텍스트를 사용하는 대화 인터페이스를 만듭니다. Chatbots(챗봇) 구축에 적합합니다.
  • Amazon Transcribe(음성을 텍스트로 변환하는 서비스): Speech-to-Text(음성→텍스트 변환)를 제공하며 녹음 내용의 자막·전사문 생성에 유용합니다.
  • Amazon Polly(텍스트를 음성으로 변환하는 서비스): Text-to-Speech(텍스트→음성 변환)로 자연스러운 음성을 생성하여 음성 기반 사용자 경험을 제공합니다.

Customer Experience(고객 경험)

  • Amazon Kendra(기업 문서 검색 서비스): 지능적인 문서 검색 기능을 제공합니다.
  • Amazon Personalize(개인화 추천 서비스): 사용자에게 맞춘 상품 추천을 제공합니다. '이런 상품도 좋아하실 수 있습니다'와 같은 기능에 활용합니다.
  • Amazon Translate(기계 번역 서비스): 여러 언어 사이의 번역을 제공하여 전 세계 사용자와의 소통을 돕습니다.

Business Metrics(비즈니스 지표)

  • Amazon Forecast(시계열 예측 서비스): 재고 수준처럼 Time-Series Data(시계열 데이터)의 미래 값을 예측합니다.

[최신 서비스 상태]공식 문서는 Amazon Forecast(시계열 예측 서비스)의 신규 고객 이용 제한과 Amazon Fraud Detector(사기 탐지 서비스)의 2025년 11월 7일부터의 신규 고객 접수 중단을 안내합니다. 원문의 개념 설명은 보존하되 실습 가능 여부와 구분하세요. 이러한 상태만으로 시험 출제 여부를 단정할 수는 없습니다. [S21] [S22]

Amazon Q(Amazon의 AI 도우미 제품군)

  • Amazon Q in QuickSight(QuickSight의 자연어 분석 도우미): Amazon QuickSight(비즈니스 분석·시각화 서비스)에 통합되어 Natural Language Querying(자연어 질의)을 제공합니다. 사용자가 비즈니스 분석 관련 질문을 하고 데이터에서 인사이트를 얻도록 돕습니다.

  • Amazon Q in AWS Supply Chain(공급망 업무용 AI 도우미): AWS Supply Chain(공급망 관리 서비스) 데이터에서 인사이트를 제공하여 재고 관리, Demand Forecasting(수요 예측), 공급망 관리의 최적화·자동화를 돕는다고 설명합니다.
[학습 보충]이 항목은 원문에 나오는 제품군과 활용 예시를 번역한 것입니다. 제품별 통합 기능이 모든 문의 처리나 업무 자동화를 기본 제공한다는 뜻은 아니며, 데이터 연결과 업무 구성이 필요합니다.

Amazon SageMaker(모델 구축·학습·배포 서비스)

개발자와 Data Scientists(데이터 과학자)가 ML Models(기계 학습 모델)을 대규모로 구축·학습·배포하도록 지원하는 통합 서비스입니다. 처음부터 맞춤형 모델을 만들거나 SageMaker JumpStart(사전 학습 모델 허브)를 통해 기존 모델을 사용하고 Fine-Tuning(미세 조정)할 수 있습니다.

Amazon Rekognition(이미지·동영상 분석) 같은 상위 수준의 AI 서비스보다 모델과 학습 과정을 더 세밀하게 제어할 수 있습니다. 프로젝트 요구사항에 맞춰 상세한 Customization(사용 목적에 맞춘 조정)과 Optimization(최적화)을 수행합니다.

[용어 안내]원문이 다루는 모델 구축·학습·배포 서비스는 현재 공식 문서에서 주로 Amazon SageMaker AI라는 이름을 사용합니다. 이 번역에서는 원문과 대조하기 쉽게 SageMaker라는 이름을 유지합니다. [S08]

SageMaker Studio(기계 학습 통합 개발 환경)

ML(기계 학습)을 위한 IDE(Integrated Development Environment, 통합 개발 환경)입니다. 하나의 인터페이스에서 데이터 준비, 모델 구축, 학습, 튜닝, 배포를 수행할 수 있습니다.

코드를 작성하는 Jupyter Notebooks(주피터 노트북), 통합 Debugging Tools(디버깅 도구), 실험 관리 기능 등을 클라우드 협업 환경에서 제공합니다. 실시간 협업과 모델 모니터링·데이터 준비 등 여러 SageMaker 기능에 대한 접근도 지원한다고 설명합니다.

Training Process(학습 과정)

일반적인 SageMaker 학습 작업에는 다음 요소가 필요합니다.

  • Training Data Locations(학습 데이터 위치): 데이터는 보통 Amazon S3(객체 스토리지)에 저장하고 S3 URLs(S3 데이터 주소)로 지정합니다.
  • ML Compute Instances(기계 학습 컴퓨팅 인스턴스): 확장 가능한 연산을 위해 EC2 Instances(EC2 가상 서버 인스턴스)를 사용합니다. 원문에는 괄호로 ECR instances라고도 적혀 있습니다.
  • Training Images(학습용 컨테이너 이미지): ML(기계 학습)용으로 준비한 Docker Container Images(도커 컨테이너 이미지)에서 학습을 실행합니다.
  • Hyperparameters(하이퍼파라미터): Learning Rate(학습률), Batch Size(배치 크기)처럼 학습 과정을 제어하는 설정입니다.
  • S3 Output Bucket(S3 결과 저장 버킷): 학습 후 생성된 Model Artifacts(모델 산출물)를 저장하여 나중에 사용합니다.
[검증 및 정정]EC2(가상 서버)는 연산 자원이고 ECR(Elastic Container Registry, 컨테이너 이미지 저장소)은 이미지를 보관하는 서비스입니다. ECR instances라는 컴퓨팅 인스턴스 유형이 있다는 뜻이 아닙니다. [S08]

Features(SageMaker의 주요 기능)

  • SageMaker Feature Store(특성 저장·공유 기능): ML Features(기계 학습 특성)를 중앙에서 저장·검색·공유합니다.
  • SageMaker Model Registry(모델 버전 등록·관리 기능): 모델의 여러 버전과 Metadata(메타데이터)를 관리합니다.
  • SageMaker Pipelines(기계 학습 작업 흐름 조정 기능): 모델 구축·학습·배포를 반복 가능한 Workflow(작업 흐름)로 구성합니다.
  • SageMaker Model Monitor(모델·데이터 품질 모니터링 기능): 내장 규칙 또는 맞춤형 규칙으로 Data Drift(데이터 드리프트)를 탐지합니다. 결과를 CloudWatch(운영 지표·로그·경보 서비스)에 보내고 후속 대응을 연계할 수 있습니다.
  • SageMaker Ground Truth(학습 데이터 라벨링 기능): 사람이 데이터를 라벨링하는 작업을 지원하여 품질 높은 학습 데이터셋을 준비합니다.
  • SageMaker Canvas(코드 없는 모델 구축 도구): 기술 지식이 적은 사용자도 화면에서 자체 데이터에 기반한 모델을 구축하도록 돕습니다.
  • SageMaker JumpStart(사전 학습 모델·솔루션 허브): Pre-trained Models(사전 학습된 모델)에 접근하고 ML Solutions(기계 학습 솔루션)를 손쉽게 배포합니다.
  • SageMaker Clarify(편향 탐지·예측 설명 기능): Bias(편향) 탐지와 예측 결과 설명을 지원하여 투명성을 높입니다.
  • SageMaker Role Manager(역할·권한 설정 지원 기능): SageMaker 자원과 서비스의 권한을 설정·관리합니다.
  • SageMaker Model Cards(모델 설명 문서 기능): 학습한 모델에 대한 목적·성능·한계 등의 설명 문서를 만듭니다.
  • SageMaker ML Lineage Tracking(기계 학습 계보 추적 기능): 모델의 생성·변경 이력을 기록하여 Governance(관리·통제), 작업 재현, 이력 관리를 지원합니다.
  • SageMaker Model Dashboard(모델 관리 대시보드): 모델 관련 활동을 통합하여 관리·모니터링하는 인터페이스입니다.
  • SageMaker Data Wrangler(시각적 데이터 준비 기능): 데이터 정리·변환·시각화를 쉽게 수행하여 ML(기계 학습)용 데이터 준비를 돕습니다.
  • SageMaker Experiments(기계 학습 실험 추적 기능): 반복적인 실험을 추적·정리·조회·분석·비교합니다. 원문은 현재 MLflow with Amazon SageMaker라는 이름으로 불린다고 덧붙입니다.
  • SageMaker Autopilot(자동 모델 구축·학습·튜닝 기능): 모델을 자동으로 구축·학습·튜닝하면서 과정에 대한 가시성과 제어권을 제공합니다.
  • Amazon Augmented AI(사람 검토 연계 서비스, A2I): 신뢰도가 낮은 예측이나 무작위 표본에 Human Review(사람 검토)를 추가할 수 있습니다.
  • SageMaker Managed Spot Training(관리형 스팟 학습): 여유 EC2 Capacity(EC2 연산 용량)를 이용하여 학습 비용을 줄입니다.
  • SageMaker Profiler(학습 자원 성능 분석 기능): 학습 작업의 자원 사용 비효율을 찾아 속도·정확도를 유지하면서 비용을 줄이는 데 활용합니다.
[검증 및 정정]SageMaker Experiments(기계 학습 실험 추적 기능)와 Managed MLflow(관리형 MLflow)를 단순히 이름만 바뀐 동일 기능으로 보지는 마세요. 공식 문서는 Experiments Classic(기존 실험 추적 기능)에서 MLflow(실험·모델 추적 플랫폼)로 옮기는 절차와 코드 변경을 별도로 안내합니다. Human Review(사람 검토)와 라벨링 도구 역시 결과 품질을 높이는 수단이며 정확성을 자동 보장하지는 않습니다. [S23]

Amazon Bedrock(기반 모델 활용 서비스)

주요 AI 기업의 고성능 Foundation Models(기반 모델, FMs)에 하나의 API(응용 프로그램 인터페이스)를 통해 접근하도록 하는 Fully Managed(완전 관리형), Serverless(서버리스) 서비스입니다. Security(보안), Privacy(개인정보 보호), Responsible AI(책임 있는 AI)를 고려하여 Generative AI Applications(생성형 AI 애플리케이션)를 구축하도록 지원합니다.

Pricing(요금)

  • Pay-as-you-go(사용량 기반 요금): 원문은 Inference(추론)에서 처리한 Input Tokens(입력 토큰)와 Output Tokens(출력 토큰) 수에 따라 요금을 낸다고 설명합니다. 사용한 기반 모델의 처리량에 따라 비용을 지불한다는 뜻입니다.
  • Fine-tuned Models(미세 조정 모델): 원문은 Custom Models(맞춤형 모델)나 Fine-tuned Models(미세 조정 모델)을 사용하면, 일관된 성능과 예약 추론 용량을 제공하는 Provisioned Throughput(프로비저닝된 처리량)에 추가 비용이 발생한다고 설명합니다.
[검증 및 정정]Tokens(토큰) 기반 과금은 주로 텍스트 모델 추론의 설명입니다. 모델·입출력 유형·사용 기능에 따라 이미지, 시간, 처리량 등 다른 과금 단위가 적용될 수 있고, 학습·보관·부가 기능 비용도 구분해야 합니다. 맞춤형 모델이 항상 Provisioned Throughput(예약 추론 용량)만 사용하는 것도 아닙니다. [S07] [S24]

Features(Bedrock의 주요 기능)

  • Model Choice(모델 선택):
    • 원문은 AI21 Labs, Anthropic, Cohere, Meta, Mistral AI, Stability AI, Amazon의 다양한 Foundation Models(기반 모델)에 접근하여 애플리케이션 요구에 맞는 모델을 고를 수 있다고 설명합니다.
    • Amazon Titan Models(Amazon이 개발한 Titan 기반 모델): 원문은 Amazon Bedrock(기반 모델 활용 서비스)에서 독점적으로 제공하는, AWS가 사전 학습한 고성능 Foundation Models(기반 모델)로 설명합니다. 다양한 활용 사례와 Responsible AI(책임 있는 AI) 관행을 고려해 설계되었다고 설명합니다.
  • Customization(사용 목적에 맞춘 조정): 자체 데이터를 비공개로 활용하여 Fine-Tuning(미세 조정), RAG(Retrieval Augmented Generation, 검색 증강 생성) 등의 방법으로 결과의 관련성과 정확성을 개선합니다.
  • Foundation Model Evaluation(기반 모델 평가): 모델을 평가·비교하여 활용 목적에 적합한 모델을 선택합니다. Accuracy(정확성), Robustness(견고성), Toxicity(유해성) 등의 지표를 활용할 수 있다고 설명합니다. 원문은 SageMaker Clarify(편향 탐지·예측 설명 기능)와 fmeval(기반 모델 평가 라이브러리)을 연계하여 편향과 설명 가능성을 확인한다고도 설명합니다.
  • Bedrock Knowledge Bases(Bedrock 지식 기반):
    • RAG(검색 증강 생성)로 비공개 데이터 출처에서 관련 내용을 가져와, 관련성과 정확성이 높은 응답을 만들도록 돕습니다.
    • Data Ingestion(데이터 수집·유입), Retrieval(정보 검색), Prompt Augmentation(검색 결과를 프롬프트에 추가하는 보강) 등 전체 RAG(검색 증강 생성) 흐름을 지원합니다.
    • 관련 외부 지식을 검색하여 생성 모델의 입력에 반영함으로써 출력 품질을 개선합니다.
  • Bedrock Agents(Bedrock 작업 에이전트): 기업 시스템과 데이터 출처를 이용하여 여러 단계의 작업을 계획하고 실행하는 Agents(에이전트)를 만듭니다. 고객 문의나 주문 처리 같은 복잡한 업무를 간소화합니다.
  • Serverless(서버리스): 사용자가 서버 인프라를 직접 관리해야 하는 부담을 줄여 AI 기능의 배포와 확장을 간소화합니다.
  • Security and Privacy Guardrails(보안·개인정보 보호를 위한 제한·검토 장치): 원문은 부적절한 콘텐츠나 금융 조언 같은 민감한 출력을 제한하여 윤리적이고 규정에 맞는 AI 사용을 보장한다고 표현합니다.
  • PartyRock(코드 없는 생성형 AI 앱 제작 실습 도구): Amazon Bedrock(기반 모델 활용 서비스)을 바탕으로, 코드를 작성하지 않고 생성형 AI 앱을 만들고 모델을 실험하는 도구입니다.
[검증 및 정정]RAG(검색 증강 생성)는 검색한 정보를 입력 문맥에 추가하는 방식입니다. Fine-Tuning(미세 조정)처럼 모델 Weights(가중치)를 바꾸는 학습은 아닙니다. Bedrock Model Evaluation(모델 평가), SageMaker Clarify(편향·설명 기능), fmeval(평가 라이브러리)도 기능과 평가 범위를 구분해야 하며, 모든 검사 기능이 자동으로 한 번에 수행되는 것은 아닙니다. [S15] [S25]
[검증 및 정정]Bedrock Guardrails(Bedrock의 입력·출력 보호 장치)는 설정한 정책으로 입력과 출력을 탐지·필터링하도록 돕습니다. 모든 유해 출력 차단이나 모든 규정 준수를 보장하는 기능은 아닙니다. 금융 주제 전체가 일률적으로 차단된다는 뜻도 아니며 Denied Topics(차단 주제) 등의 정책 설정에 따라 달라집니다. [S26]

AWS Glue(데이터 통합·변환 서비스)

분석과 AI 모델에 사용할 데이터를 준비하고 적재하도록 돕는 Fully Managed(완전 관리형), 클라우드 기반 ETL(Extract, Transform, Load, 추출·변환·적재) 서비스입니다.

Features(Glue의 주요 기능)

  • AWS Glue ETL Service(Glue의 추출·변환·적재 기능):
    • 중복 제거와 결측값 처리 같은 내장 변환으로 데이터를 준비합니다.
    • 원문의 예시 흐름: Amazon Kinesis Data Streams(실시간 데이터 스트림 수집) → AWS Glue ETL Job(추출·변환·적재 작업) → CSV-to-Parquet Conversion(CSV에서 Parquet 형식으로 변환) → S3 Data Lake(S3 기반 데이터 레이크).
  • AWS Glue Data Catalog(데이터 메타데이터 카탈로그): 원문은 ETL(추출·변환·적재) 작업을 관리·모니터링하는 중앙 저장소이며, 내장 Classifiers(데이터 형식 분류기)로 데이터 자체가 아닌 Metadata(메타데이터), 즉 Schemas(스키마)를 저장한다고 설명합니다.
  • AWS Glue DataBrew(시각적 데이터 준비 도구): 화면에서 데이터를 준비하고 품질 규칙을 정의하며, 변환 과정을 Recipes(재사용 가능한 변환 단계 모음)로 저장합니다.
  • AWS Glue Data Quality(데이터 품질 관리 기능): Anomalies(이상 징후)를 탐지하고 Data Quality Rules(데이터 품질 규칙)를 추천하여 AI 모델에 사용할 데이터 품질을 높입니다.
[검증 및 정정]AWS Glue Data Catalog(데이터 카탈로그)의 핵심은 데이터의 위치·스키마·속성 등 Metadata(메타데이터)를 저장하는 것입니다. ETL Job Execution(ETL 작업 실행) 자체를 관리하는 엔진과 구분하세요. Crawlers(데이터 원본을 탐색하는 크롤러)가 Classifiers(형식 분류기)를 활용하여 데이터를 분석하고 카탈로그를 채울 수 있습니다. [S12]
